# Rules: checks, harness, browser tests

Part of the agent manual (`CLAUDE.md`). Read this before you run or change a check, use the harness, or test in a browser.

- The tag at the end of a rule is the session that wrote it; rules written after Session 20 carry their date. **If two rules disagree, the later one wins** (date > `S20 …` > `S19` > … > `≤ S9`).
- Rules without a tag come from the former "Testing" section of `CLAUDE.md`, which every session kept current.
- Sandbox limits for browser runs (2 GB RAM, software GL): `git-sandbox.md`.

## `npm run check`
- **`npm run check`** (≈ 60 – 80 s in the 2-CPU sandbox, node only): typecheck (covers `src`, `tools/ci` and `tools/harness`), `tools/ci/unit.ts` (unit checks), `tools/ci/pods.ts` (pod audit, see `pods.md`), then `tools/ci/sim.ts` – fails on NaN, deaths > 3, wall penetration > 0.6 m, ground clearance < 0.2 m, pod slower than 18 m/s. `DEBUG=1`, `TRACK=<id>`, `SECS=<n>`, `PITCH_AIR=1|0|-1` (jump experiment).
- **Unit checks:** `tools/ci/unit.ts` (`npm run check:unit`, `ONLY=<text>`): tiny `test` / `eq` / `throws` helpers for pure logic. Write the check first, watch it fail, then the code. *(S20 Pods)*
- **The sim's tracks share one random stream:** a change that alters one track's run shifts every later row. Compare track by track (`TRACK=<id> node tools/ci/out/sim.mjs`) before calling a table change a regression. The deck self-test does not lift pod 1 in the last 2 s of a run (it would end before the 20 deck frames). *(S20 Strecken)*
- **Session 20 (Pods) tests:** `npm run check:pods` (≈ 6 s; `POD=<id>`, `UPDATE=1`, `HULL=write` measures the hulls in `src/game/podHulls.json` again); harness `statsAll()` must match the audit numbers after any change to `podModel.ts` / `podAssembly.ts`; before/after sheets saved with `save:` are byte-identical when nothing visible changed.

## Real app and WebGPU (Puppeteer)
- **App smoke test:** `node papp.mjs <dist/index.html> <out prefix> '<profile json>'` after `npm run build`. Harness extras: `?ultra`, `?rt=<race seconds>`, `wx=front`.
- **Real-app test:** `tools/harness/papp.mjs` (Puppeteer). Match UI text via `textContent` (CSS uppercases `innerText`). Software rendering runs the game ~16× slow: wait for the `LOS!` message instead of fixed times. *(S12)*
- **`npm run check:gpu`**: `tools/ci/gpu.mjs` – WebGPU console check (`PUPPETEER_DIR`, `TRACKS=0,5`, `QUERY='?csm'`). Harness view `r` = 2.8 s of real racing (live particles/banking).
- **No Playwright?** Use Puppeteer: `tools/harness/pshot.mjs` (setup + commands: „Test-Setup" at the end of this file). Screenshots need `?webgl`; WebGPU run = console-error check only (white screenshots in headless Chrome 148).
Headless WebGPU: `tools/harness/run.sh game "t0:a,t4:j,t2:q"` and `"s8:30"`. Views `j` = crossing bridge/underpass, `q` = cave fork. Track indices (13): 0 boonta, 1 frost, 2 magma, 3 dunepass, 4 jungle, 5 aquilaris, 6 oovo, 7 crystal, 8 malastare, 9 mosespa, 10 howler, 11 methane, 12 executioner.

## Browser pane hidden (in-app browser)
- **Hidden browser pane, easier way (replaces stepping by hand):** right after `navigate`, before starting the race, give the page a timer-driven frame clock: `window.requestAnimationFrame = cb => setTimeout(() => cb(performance.now()), 16); window.cancelAnimationFrame = id => clearTimeout(id);` – game loop, three's frame counter and the WebGL2 fallback's shader-compile polling then run in real time (without it the WebGL2 app never leaves the loading screen while the pane is hidden). Then wait for `__podracer.state === 'race'`. *(S20 Pods)*
- **In-app browser pane hidden → `requestAnimationFrame` does not fire** (the race stays in the countdown). Step the game by hand: `const g = __podracer; g.keys.add('KeyW'); let now = g.lastT; for (…) { now += 1000 / 60; g.loop(now); cancelAnimationFrame(g.raf); }`, then `g.lastT = performance.now(); g.raf = requestAnimationFrame(g.loop);` – otherwise the next real frame gets a negative `dt` (`Game.loop` only caps it from above). Never cancel all rAF handles: three.js counts its frames in its own rAF loop, without it the camera uniforms freeze. Take pictures with the browser's screenshot tool (`canvas.toBlob` returns an old frame). Let the AI drive the own pod: `const m = await import('/src/game/physics.ts'); g.readInput = () => { const p = g.player; p.ai = { skill: 0.9, speedF: 0.9, lineOff: 0, takeShortcut: false, boostUntil: 0, repairMode: false, noiseT: 0, rubber: 1 }; m.aiInputs(p, g.td, g.pods, g.raceTime, null); p.ai = null; };`. The harness is unaffected (it renders with `renderAsync`). *(S20 Pods)*

## Test-Setup in frischer Sandbox (≈ 4 Min.; `.git` fehlt? → `npm run restore-git`)

2. `sudo apt-get update && sudo apt-get install -y --no-install-recommends libnspr4 libnss3 libatk1.0-0 libatk-bridge2.0-0 libdbus-1-3 libxcomposite1 libxdamage1 libxfixes3 libxrandr2 libgbm1 libxkbcommon0 libasound2 libatspi2.0-0 libcups2 libcairo2 libpango-1.0-0`
3. `cd <repo> && git checkout -- tools/harness/out && cd tools/harness && npx esbuild game.ts --bundle --format=esm --loader:.jpg=dataurl --outfile=out/game.js && cp pshot.mjs papp.mjs /tmp/t/`
4. `cd /tmp/t && node pshot.mjs <repo>/tools/harness/out/game.html "t0:e,t5:b" /tmp/t/out "?webgl"` → `/tmp/t/out_grid.jpg` (≈ 35 s pro Strecke)
5. Seit Session 20 (Fotosets): **eine Strecke je Lauf** (≈ 50 s Laden + 12–18 s je Ansicht), immer mit `timeout 285 …`; `/tmp` ist ein RAM-Laufwerk – alte Screenshots und `/tmp/puppeteer_dev_chrome_profile-*` löschen. WebGPU-Check: `PUPPETEER_DIR=/tmp/t TRACKS=1 QUERY='?tex=256' npm run check:gpu`.
