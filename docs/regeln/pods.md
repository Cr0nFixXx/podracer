# Rules: pods (Racer)

Part of the agent manual (`CLAUDE.md`). Read this before you change a pod: geometry, cockpits, engines, Teile, Schadensmodelle, the look of the Gegner.

- The tag at the end of a rule is the session that wrote it; rules written after Session 20 carry their date. **If two rules disagree, the later one wins** (date > `S20 …` > `S19` > … > `≤ S9`).
- Design intent: `DESIGN.md` → „Racer (Pods)". Phase table, decisions and measurements of the pod overhaul: `docs/verlauf/2026-11-21-session-20-pods.md`.
- How the hull is used against tunnel vaults and overheads: `physik-steuerung.md`. Audit commands and the pods harness: `tests.md`.

## Where pod code lives
- **Removed as dead code (2026-11-22):** `cockpit.style` / `CockpitStyle`, `cockpitExtras` (its Bruchteile would have gone in untagged), `cockpitDesigns`, and the `glass` / `skin` entries of `sharedPodMaterials` (the canopy glass comes from `canopyGlass`, the skin from `skinMaterial`). `DebrisPool.dispose` is called from `Game.dispose` for both pools. *(2026-11-22)*
- **Pod geometry is assembled in `podAssembly.ts`** (material-free: engine banks, cockpit, cables, binders, far LOD, vertex-colour bake for Gegner). `podModel.ts` only adds materials, meshes and animation. `podAssembly.ts`, `podKit.ts`, `podParts.ts`, `podDesigns.ts` must stay free of `three/webgpu`, TSL and DOM imports – the node audit bundles them. *(S20 Pods)*
- **Where pod code lives (Phase 1 split):** `podLayouts.ts` = one entry per pod id in `LAYOUTS` (engines, cockpit, `binders: { a, b, zOff }[]`, `engineExtras` / `cockpitExtras`, `extraCircles`, `envelope`) – **an unknown id throws**, no hard-coded pod ids anywhere else. `podCockpits.ts` = cockpit + pilot geometry (`PilotDef.head` picks the head, never the species name). `podParts.ts` = engines + `engineExtent(spec)` (the single source for collision radius, ground-clamp bottom / side, cable height). `podDesigns.ts` = only `podCollision` / `podEnvelope` (now with `axisY`, `cockpit.topY`, `length`). `PodDef` no longer carries sizes (`engine`, `engineLen`, `engineRad`, `spread`, `cable`, `cockpit` are gone). *(S20 Pods)*
- **A bucket that cannot be merged throws** (before: silently dropped). Every part that goes into one material bucket needs the same vertex attributes. *(S20 Pods)*

## Audit, baselines, budgets, hull
- **Pod audit (`tools/ci/pods.ts`, first part of `npm run check`):** mesh + triangle counts of every build (player quality 1–3, Gegner near at quality 2 / 3, far LOD) must equal `tools/ci/pods-baseline.json`. Pods changed on purpose → `UPDATE=1 npm run check:pods`, paste the rows, write the reason into the task's file in `docs/verlauf/`. `TOL` in the audit = how far the visible model may exceed `podCollision` / `podEnvelope`. *(S20 Pods)*
- **Old pods keep their physics size:** `tools/ci/pods-shapes.json` holds every pod's collision circles + envelope; the audit fails when they move. New pods: add their row on purpose (`UPDATE=1`). *(S20 Pods)*
- **Budgets (audit, `BUDGET` in `tools/ci/pods.ts`):** below Ultra the player pod ≤ Session 19 × 1.2 and a near Gegner ≤ Session 19 (`budgetRef` in `pods-baseline.json`, never edit); Ultra: player ≤ 250k triangles / 110 draws, near Gegner ≤ 100k / 60; far LOD ≤ 1.1k / 3. Take new numbers over with `UPDATE=write npm run check:pods` (`NOTE="why"`). *(S20 Pods)*
- **`podHulls.json` is measured, never edited by hand.** After changing a pod's layout, a cockpit, an engine style or a Style-/Tuning-Teil run `npm run check:pods`: column `hull` fails when the model reaches > 2 cm out of its hull, column `stale` when the hull is > 9 cm larger than the model; a pod without a hull fails. Measure again with `HULL=write npm run check:pods` (measuring code `tools/ci/hull.ts`: factory pod at detail 1–3 + the audit's three Teile outfits) and say why in the task's file in `docs/verlauf/`. Unit checks (`ONLY="tunnel ceiling" npm run check:unit`, `ONLY=overheads npm run check:unit`; `CEIL_TABLE=1` prints every case): pushed up against the vault no corner is inside it or short of it · every pod fits under every tunnel · a riding pod is never pressed down · a pod that flies into a gantry or an arch is knocked down by its own height. *(S20 Strecken)*

## New pods, engines, geometry
- **Ring wing of the hoop engine (Lyss Halo-9):** the end plate of a ring segment is the polygon `END_PLATE` (`podEngines.ts`) – it must lie inside the ring section with the bevel that `plateYZ` adds (`plateBevel`); the unit check "Lyss Halo-9: the end plate …" measures it against the built skin (a plain bar stood 4 cm proud at both edges). Rivets are pins sunk into the skin (head 4 mm proud at a rib): a part placed on the true circle floats over the flats of a lathe with few segments (sagitta 1.2 cm at 24 segments). *(2026-11-22)*
- **Rules for a new pod:** lowest point ≥ −1.9 m under the pod origin, half width ≤ 4.6 m, ring / hoop radius ≤ 1.85 m, no `keel` (unit checks "new racers: …"); `engineExtent().top` = top of the solid body (a ring you can see through does not count – the cockpit-height rule and the cable routing use it); append the pod to `PODS` after the ten old ones (the old CI grid counts on their order); take its numbers over with `UPDATE=write NOTE="why" npm run check:pods`. *(S20 Pods)*
- **Four new pods (Phase 3: `cyclone`, `halo`, `manta`, `volt`) and their engine styles (`podEngines.ts`):** `rotor`, `hoop`, `slab`, `cage` have builders of their own, hooked in through `OWN_ENGINES` / `OWN_EXTENTS` (looked up first in `engineGeo` / `engineExtent`). Never add a new style as a branch of the round builder in `podParts.ts` – that file must not change for the ten old pods. Same `EngineGeo` contract: `parts`, `fan` (+ `fanMat`, `fanSpin`), `flaps` (hinged at the front edge, turn about the vertical axis only), `petals` (attribute `aPet`), flames (attribute `aLiv`, from `flameGeo` in `podKit.ts`), `pylon`, `binder`. `openRotor: true` = the fan is a big open rotor: Gegner show it as its own turning mesh (`RivalBank.rotors`, shared material). `podEngines.ts`, `podLayouts.ts`, `podCockpits.ts`, `roster.ts` must stay free of `three/webgpu`, TSL and DOM like the other audited files. *(S20 Pods)*
- **Geometry traps found in Phase 3:** a `lathe` profile must run towards +z for an outer skin (towards −z the faces point inwards – right only for inner skins); parts at the lowest point of a pod are built from straight tubes (`rail` in `podLayouts.ts`) – a spline through the same points dips below them and fails the audit. *(S20 Pods)*
- **Energy binders:** one mesh per engine pair (`binderGroups` / `mergeBinders` in `podAssembly.ts`); several arcs between the same two engines = several `binders` entries with `zOff` (Voltspire: three arcs, one mesh, all ≥ 2.5 m behind the engine front). *(S20 Pods)*
- **Detail levels:** `segFor` / `detailFor` in `podAssembly.ts` – player 20 / 28 / 40 segments, Gegner 14 and **28 on Ultra**; cockpit detail 0 = lite (Gegner below Ultra: `k.hi` false, simple pilot), 1 = full, 2 = Ultra extras (`k.ultra`). Layout extras get `(pb, L, hi)`; engine detail pass is gated by `seg >= 24`, Ultra parts by `seg >= 40`. *(S20 Pods)*
- **Pod layouts may define several binders** (`PodLayout.binders`); hero and rival builders loop over them, A is always the left-hand engine. Binder look = `boltLook` (thin core + 4 independent arcs). *(S17)*

## Cockpits, pilots, cockpit camera
- **Cockpit height (user request at the Phase 2 stop):** a cockpit rides above the engine line – tub floor not below the lower engines' axis, pilot's eye ≥ 0.25 m above their top (unit check "cockpit height"). The ten old pods use `...raised(y, up)` in their layout: visible height `y + up` **and** `keel: up`. `cockpit.keel` only lowers the ground clamp (`podEnvelope().cockpit.minY` = tub floor − keel), so those pods drive exactly as before; everything visible (cables, eye, strobe `topY`, far LOD, Gegner) follows `cockpit.y`. To move a cockpit, change the second number of `raised(…)`; a new pod leaves `keel` out. *(S20 Pods)*
- **Cockpits (`podCockpits.ts`, Phase 2):** one design function per pod in `DESIGNS` (layout `cockpit.design`, default = pod id; unknown design throws), built from the kit (`shell`, `seat`, `pilot`, `levers`, `dash`, `windscreen`, `anchors`, `belly`, `part`). Rules: cockpit-local +z = forward; nothing lower than `-(0.68·hw + 0.14)` (audit `lowCk`); every design calls `dash()` (three live lamps) and returns `head`, `eye`, `anchors`; mirror with `M4.mirrorX()` in the matrix, never `geometry.scale(-1, …)` (flips the lighting). `part(k, id, …)` registers a Bruchteil (the assembly tags its triangles; an id the racer's Schadensmodell does not name stays plain cockpit). *(S20 Pods)*
- **Cockpit camera (ADR 0003):** `PodVisual.setCockpitView(inside)` + `eyeWorld(out)`; the pilot's triangles are merged LAST into each cockpit bucket (`HeroAssembly.pilotStart`) – keep that order. `cockpit.viewScale` in the layout overrides the computed enlargement. Dash lamps = one vertex-coloured mesh (`LAMP_VERTS` per lamp), colours set in the hero `update()`. *(S20 Pods)*
- **Pilots:** `PilotDef.head` (figure variant: `goggles | snout | crest | aero | dome | maul | veil | horn | optic`, every variant needs a lite branch) + `skin` (colour via `skinMaterial`); far-LOD silhouette cue = `cockpit.far` (`box | disc | fin | cage | ring`); the far engines follow the style (ring round `rotor` / `hoop`, flat box for `slab`). *(S20 Pods)*
- **Cockpit pendulum:** physics state `ckX/ckY/ckZ` (stepPod), visual via `setCockpitSway` (cockpit group + cable uniform `uCk`); Session 20 (Pods): the cockpit camera shows the cockpit from inside (`setCockpitView`, ADR 0003: pilot hidden by draw range, cockpit enlarged about the eye) – still do not lower the camera near plane. *(S17)*

## Tuning-Teile and Style-Teile
- **Tuning-Teile + Style-Teile (Phase 4, `podKitParts.ts`):** `engineKit(spec, seg, kit)` adds parts on the hard points of an engine (`EngineGeo.hard: HardPoints` – nozzle, mouth, spikeZ, body, spine, tail, `sideMax` / `bottomMax`). **Every engine builder must return `hard`**; flat engines set `slot: [halfW, halfH]` and get the flat variants. Kit parts go into the engine's material buckets and never replace factory geometry (factory goldens + `pods-shapes.json` stay untouched). `KitSpec = { fins, intake, nozzle, tune }`: Style-Teil choices 0..3 (`PodCustom.kit`, labels in `KIT_SLOTS`, clamped in `sanitizeCustom`), `tune` = tiers from `tuneTiers(tuning)` (step 0–1 → 0, 2–3 → 1, 4–5 → 2). The fourth slot (Kanzel) is a material: `canopyGlass(tint)` in `podMaterials.ts` (4 shared glass materials). Player = Style-Teile + Tuning-Teile; Gegner = Style-Teile only, from `rivalKit(seed)` (`roster.ts`). New choice or tier → branch in `engineKit` (round + `slot` variant), label in `KIT_SLOTS`; the unit checks "kit: …" run it on every engine style and the audit builds three sets per pod (lines `kit: …`: meshes, triangles, wide, low; limits = Ultra budgets, `TOL.wide`, `TOL.lowEngine`). Extra flap leaves (`FlapGeo.gain`) are the only extra meshes. `podKitParts.ts` stays free of `three/webgpu`, TSL and DOM. Harness: `show(idx, hp, q, { kit: { fins, intake, nozzle, canopy }, tune: { topSpeed: 5, … } })`. *(S20 Pods)*

## Damage: Schadensmodelle, Bruchteile, Treffermarken
- **Wall hits take their zone from the nose** (user decision 2026-11-22): the wall contact in `stepPod` calls `hitZone(p, nx, nz)` – read BEFORE the nose is turned along the wall: steeper than 30° to the wall = `front`, anything else = `side` (the same rule as for obstacles). So Rammbug and hard nose help against a wall too. A guard rail only hurts a pod that flies low (`p.pos.y - 0.9` at or below the rail top); above it the energy field catches the pod without damage – rock always hurts. Unit checks "walls: …" (a rock wall on Boonta, both rules A/B-tested). *(2026-11-22)*
- **Pod against pod: ONE `pod` event per contact, and the player gets it** when the player is one of the two (`collidePods`) – Treffermarke and full-volume hit also when the Gegner comes first in the field. Never push the event to both pods (two spark bursts, two sounds). *(2026-11-22)*
- **A Gegner the player hits SHOWS it (2026-11-25):** the player's `pod` event names the other pod and what it lost (`e.pod`, `e.dealt`). `Game.updateVisuals` then puts sparks, a burst of fire and dark smoke (`Particles.ramPuff`) and a Treffermarke on the GEGNER's flank, and the HUD shows „Treffer · <Name> · <weaker engine> %" for 3.5 s (`Game.ramPod` / `ramT` → `HudState.ram`, „Zerstört" when it exploded). A Gegner's engine smokes below `RIVAL_SMOKE` 60 % wherever the player can see it (it used to smoke below 40 %, only 22–62 m from the camera, at a third of the player's density – a Gegner beside the player never showed anything). Smoke alone between two dark pods is invisible in a still: the short fire burst is what the eye catches. Harness view `ram_<idx>[_<rams>[_<m/s>[_<close camera 0|1>[_<later 1>]]]]`; `papp.mjs` checks the HUD line.
- **A Treffermarke sits on the skin the hit meets first:** `skinPoint(geo, axis x, axis y, dx, dy, z, zWin, out)` (`podAssembly.ts`, no materials, unit-checked) searches the DRAWN triangles of the bank's `hull` bucket for the outermost corner near the ray of the hit. Never put a mark "on the barrel radius" (`geo.R`): on a slab it lay a metre inside the flank, on a ring wing and a rotor hoop on the core. A Bruchteil that has dropped off gets no mark (the search stops at `drawRange.count`). *(2026-11-22)*
- **HUD wording of a lost Bruchteil** (`lost` in `podDamage.ts`): `ausgefallen` / `erloschen` only for what stays on the pod and stops working (an engine flames out, an arc dies); a part whose triangles are hidden is `abgerissen` (the default) or the like (`geplatzt`). The unit check "Bruchteile: the HUD says what the player sees" enforces it. *(2026-11-22)*
- **Engine health is only changed in `applyDamage(p, side | 'both', amount, zone)`** (`physics.ts`; zones `front | side | top | belly | heat`). Stat / AI factors, cooldowns and `invuln` stay at the call site. Handling effects of lost parts go through `PodState.fx` (`PodFx`, multiplied in `podParams`; `vmax0` = undamaged top speed for the camera FOV). The geyser loop exists twice on purpose (`Game.update`, `tools/ci/sim.ts`): unifying it changes the sim's float arithmetic (`12 / 60` vs `12 * dt`) and with it the baseline table. *(S20 Pods)*
- **Schadensmodelle (Phase 5, `podDamage.ts` – no three import, bundled into the node CI):** one `DamageModel` per pod id in `MODELS` (**unknown id throws**): `armor` per Panzerzone + `parts: Bruchteil[]`. Rules the unit checks enforce: zone factors of an intact racer average 0.9–1.1 (each 0.4–1.3); **every HUD box has exactly one Bruchteil per step 50 / 35 / 20** (`side` −1 = hpL, +1 = hpR, 0 = centre part, counts for both boxes); `fx` multipliers 0.90–0.95 (`heatRate` 1.05–1.10), `guard` 0.5–0.9; no two racers alike. `applyDamage` = zone factor (`zoneFactor`: armour × guards still attached on that side) → health → break (`partsDue`, bit mask `PodState.parts`, event `{ type: 'part', part: index }`, `fx = partsFx(model, mask, !isPlayer)`: capped at `FX_CAP` 15 %, halved for Gegner). Parts return only in `respawn` (ADR 0001) – never restore them on repair. HUD: `partLamps` → `HudState.partsL / partsR`, swapped only in `Game.hud()`; message from `lostMessage`. A/B: `DAMAGE_RULES.armor / .parts` (CI env `ARMOR=0`, `PARTS=0`) – **both off must print the table from before Phase 5**, so damage code must stay float-neutral when switched off. Bruchteil ids are what Phase 6 hides on the model (`…L` / `…R` for pairs). *(S20 Pods)*
- **Bruchteile on the model (Phase 6):** a Bruchteil is tagged where it is built – `pb.brk(id, () => { …adds… })` (`PartBuilder`, engine builders + `engineExtras`) or `part(k, id, …)` (cockpits); **ids = the ids in `podDamage.ts`** (`…L` / `…R` by engine side, x < 0 = L). Engine builders use flank ids `'blade-'` / `'blade+'` (engine's own −x / +x flank): only the pod's outer flank becomes the Bruchteil, the other one stays plain geometry. Switch-type Bruchteile live in the layout: `flameOut` / `fanLoss` (engine indices) and `arcLoss` (binder indices). **No extra meshes:** `podAssembly.ts` merges tagged geometry into the normal buckets and records index runs (`Tagged`, `BreakShow.ranges`; every push into a bucket must go through `Tagged.push` or the offsets are wrong); `podModel.ts → Hider` rewrites the index buffer without the lost runs (`visibleIndices`, also used for the pilot in the cockpit camera, id `#pilot`). So bucket geometry must be indexed and owned by the model. `PodVisual.setParts(mask)` is called every frame from `PodState.parts`. The unit check "every part of every Schadensmodell has something to show" fails when an id has no tag. Collision shapes never change with lost parts (look only). Treffermarken = `HullU.uHits` (4 × vec4 per hero hull material, mesh-local position + strength), set through `PodVisual.hitMark`, cleared on respawn. *(S20 Pods)*
- **Rules from the final review (Session 20 (Pods)):** (1) Anything an event places on a pod is converted with `worldToBody(p, bodyZ, v)` / `bodyToWorld` (`physics.ts`, pose of THIS step) – never with `body.worldToLocal` / `localToWorld` in the event loop of `Game.updateVisuals`: there the model's matrices still hold last frame's pose (1.7 m at 100 m/s). `PodVisual.hitMark(x, y, z, strength)` and `partBody(i, out)` work in body space. (2) Every mesh that uses a hero hull material has its geometry in the space the Treffermarken are measured in (engine bank / body): the flaps come as `HeroFlap` (bank-space geometry + `hinge`), hung on a hinge group with `mesh.position = -hinge`. (3) `heatAlong(geo, z0, len, dz)` (`podKit.ts`): hull parts in livery mode 0 / 3 carry their place along the engine in `aLiv.y` (engines + their Bruchteile + flaps: `placeHeat` in `engineGeo`; kit parts: `engineKit`; layout extras: `addSideExtras` with `bankSpan`). A new source of hull geometry on an engine bank must call it, or its flat plates glow white-hot like the nozzle. (4) Kit lights (`glow` of `engineKit`) get the engine's flame-out id like the factory lights. (5) The unit checks "Bruchteile: hidden triangles …" run on player and Gegner builds with kits (`breakRunsOk`: runs are whole parts, no overlap, right side, plume runs and arcs inside their meshes). *(S20 Pods)*
- **Gegner damage look (Phase 7):** the shared Gegner hull material reads `mesh.userData.scorch` (0..1), the shared flame material `mesh.userData.power` (TSL `userData`, one pipeline for all Gegner). **Every mesh that uses one of these two materials must define its key** (`addBuckets` sets `scorch = 0` on hull meshes, the plume mesh gets `power = 1`) – an undefined value is uploaded as garbage. The rival `update(t, throttle, boost, airbrake, dmgL, dmgR)` sets both from HEALTH fractions. Proof to repeat after touching pod materials: at the countdown `__podracer.renderer._pipelines.caches.size` (100 on Boonta, 11 pods, preset "Hoch") and `renderer.info.memory.programs` (166) must not grow, also not after damaging every pod. *(S20 Pods)*
- **`podModel.update(…, dmgL, dmgR, …)` receives HEALTH fractions** (1 = intact) despite the names. *(S14)*

## Look: nozzle petals, flaps, heat, paint
- **Pod upgrades:** `PodCustom` supports `pattern` (0..5) + `finish` (0..2). *(S19)*
- **Hull heat glow** = `uHeat` in `hullMaterial` (temperature falls off along `aLiv.y` from the nozzle); the hero model feeds a lagged value (`glowH`). The cockpit uses its own hull instance (`hullC`, no heat). *(S17)*
- **Boost opens the nozzle petals, never the side flaps.** Petals = `EngineGeo.petals` (attribute `aPet`: outward dir xy + swing z), ONE shared `petalMaterial()`; opening per mesh via `mesh.userData.open` (TSL `userData`). Hero: `petals[]` in `update()`; rivals: `oppPetals` in the opponent `update(t, throttle, boost)`. Side flaps = air brake (+ damage rattle) only. *(S16)*
- **No number plates / signs on pods** (user dislikes them). *(S16)*
- **Pod extras:** number plates were removed again in Session 16 (there is no `numberPlate()` and `buildPodModel` has no `num` parameter: `buildPodModel(def, colors, quality, texRes, isOpponent, opts)`); `boostK` in the hero `update()` now drives the nozzle petals. *(S15)*

## Who races
- **Who races:** `roster.ts → pickRivals(playerId, n, rnd?)` draws the Gegner afresh for every race (never the player's pod, never twice). CI grid: `tools/ci/roster.ts → ciRoster(track)` moves on by three pods per track; `ROSTER_OLD=1 node tools/ci/out/sim.mjs` runs the Session 19 grid – its table must equal the previous phase whenever the old pods must not drive differently. *(S20 Pods)*
